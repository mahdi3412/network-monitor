# Network Monitor

سیستم مانیتورینگ و موجودی شبکه (در سبک Lansweeper) شامل دو بخش:

1. **Agent ساده سمت کلاینت** (`client/`): روی هر سیستم نصب می‌شود و فقط اطلاعات هویتی همان سیستم را می‌فرستد.
2. **پلتفرم مدیر شبکه** (`dashboard/`): روی سرور اجرا می‌شود، شبکه را خودش کشف می‌کند و همه اطلاعات را یکجا نشان می‌دهد.

## Agent

هر ۶۰ ثانیه این اطلاعات ارسال می‌شود (فاصله را سرور تعیین می‌کند؛ پایین را ببینید):

- IP و MAC (کارت شبکه‌ای که default route از آن می‌گذرد؛ کارت‌های مجازی/VPN نادیده گرفته می‌شوند)
- نام کامپیوتر
- نام کاربری ویندوز و دامنه
- نام و نسخه ویندوز (از رجیستری، مثلاً `Windows 11 Pro 23H2 (build 22631.4602)`)
- CPU، RAM، gateway و DNS

**نام، نام خانوادگی و شماره پرسنلی در ایجنت وارد نمی‌شوند.** سرور آن‌ها را از روی نام کاربری کاربر لاگین‌شده از Active Directory پیدا می‌کند.

Agent هیچ اسکن شبکه‌ای انجام نمی‌دهد؛ کشف شبکه فقط سمت سرور است.

### اجرا

```
npm install
npm run client            # با پنجره
npx electron client/electron/main.js --hidden   # پس‌زمینه، بدون پنجره (مناسب GPO)
```

آدرس سرور از داخل پنجره (یا برای استقرار انبوه، از فایل تنظیم سراسری که اسکریپت نصب می‌نویسد) تنظیم می‌شود؛ فاصله heartbeat را سرور تعیین می‌کند. فقط یک نمونه از Agent هم‌زمان اجرا می‌شود.

شناسه و کلید ایجنت در `C:\ProgramData\NetworkMonitor` ذخیره می‌شود تا هر کامپیوتر (حتی با چند کاربر) فقط یک رکورد داشته باشد.

### نصب روی کلاینت‌ها

```
npm run build:agent      # خروجی: client\dist\win-unpacked
```

نصب خودکار با GPO/SCCM/Intune و Scheduled Task: راهنمای کامل در [`deploy/README.md`](deploy/README.md).

## سرور (داشبورد)

```
npm run dev      # توسعه: http://localhost:3000
npm run build && npm start
```

تمام تنظیمات سرور با متغیرهای محیطی است؛ نمونه کامل آن در [`dashboard/.env.example`](dashboard/.env.example) است (کپی به `dashboard/.env.local`).

سرور شبکه را خودش هر ۱۵ دقیقه (`NETWORK_SCAN_INTERVAL_SECONDS=900`) اسکن می‌کند. اسکن هر میزبان زنده چند فرآیند (ping، پورت، nbtstat، WMI) اجرا می‌کند؛ برای شبکه بزرگ فاصله کمتر از ۵ دقیقه توصیه نمی‌شود.

### نصب سرور به‌صورت خودکار (ویندوز)

```
npm install
npm run build
# PowerShell با دسترسی Administrator:
.\deploy\install-server.ps1 -Port 3000 -RemoteAddress 10.0.0.0/8,192.168.0.0/16
```

این اسکریپت یک Scheduled Task برای اجرای سرور هنگام بوت (با حساب SYSTEM و راه‌اندازی مجدد در صورت خرابی)، یک بکاپ روزانه و یک قانون فایروال می‌سازد. چون داشبورد احراز هویت ندارد، `-RemoteAddress` را فقط به زیرشبکه‌های کلاینت‌ها و آدرس مدیران محدود کنید. با AD در حالت `integrated` سرویس با حساب کامپیوتری همان سرور به AD می‌رود. حذف: `deploy\uninstall-server.ps1` (دیتابیس پاک نمی‌شود).

### پایش و بکاپ

- **سلامت:** `GET /api/health` — تعداد کلاینت‌ها، آخرین heartbeat، آخرین اسکن، وضعیت همگام‌سازی AD و حجم دیتابیس. وضعیت `ok` یا `degraded` (با فهرست هشدارها)؛ کد 503 یعنی خطای دیتابیس. برای پایش (Uptime Kuma و مشابه) مناسب است.
- **بکاپ:** `npm run backup` (یا `node dashboard/scripts/backup.mjs`) یک نسخه سازگار از دیتابیس در `data/backups` می‌سازد و `BACKUP_KEEP` (پیش‌فرض ۱۴) نسخه آخر را نگه می‌دارد. بازیابی: سرور را متوقف کنید و فایل بکاپ را به جای `data/network-monitor.db` بگذارید (فایل‌های `-wal` و `-shm` را هم پاک کنید).

### صفحه موجودی (`/inventory`)

جدول کامل سیستم‌ها با جستجو و صفحه‌بندی سمت سرور (مناسب ۱۰۰۰ کلاینت):

- جستجو روی IP، MAC (با `:` یا `-`)، نام کامپیوتر، نام کاربری، نام و نام خانوادگی، شماره پرسنلی و نسخه ویندوز؛ چند کلمه با هم (AND) جستجو می‌شوند.
- فیلتر وضعیت (آنلاین / اخیراً دیده‌شده / آفلاین) و مرتب‌سازی با کلیک روی سرستون‌ها (IP به‌صورت عددی مرتب می‌شود).
- تشخیص **IP، MAC و نام کامپیوتر تکراری** بین سیستم‌هایی که اخیراً دیده شده‌اند (نشانه تداخل IP یا کلون image).
- خروجی Excel (CSV با پشتیبانی فارسی) با همان فیلترها.
- کلیک روی هر سیستم: جزئیات کامل و تاریخچه تغییر IP، نام کامپیوتر و کاربر.

API متناظر: `GET /api/inventory?q=&status=&dup=1&sort=&dir=&page=&pageSize=&format=csv`.

### دستگاه‌های بدون Agent (`/inventory/unmanaged`)

دستگاه‌هایی که اسکن سرور دیده ولی Agent ندارند (چاپگر، سویچ، سیستم‌هایی که هنوز Agent ندارند). یک میزبان «بدون Agent» حساب می‌شود اگر هیچ کلاینتی با همان IP (با Agent اخیراً دیده‌شده)، همان MAC یا همان نام کامپیوتر (بدون پسوند دامنه) نداشته باشد. جستجو، فیلتر نوع دستگاه، بازه زمانی «دیده‌شده در N روز»، صفحه‌بندی و خروجی CSV دارد. API: `GET /api/inventory/unmanaged`.

### تنظیمات مقیاس (تا ۱۰۰۰ کلاینت)

| متغیر | پیش‌فرض | توضیح |
|---|---|---|
| `HEARTBEAT_INTERVAL_SECONDS` | `60` | فاصله heartbeat همه ایجنت‌ها؛ سرور در پاسخ heartbeat آن را به ایجنت اعلام می‌کند |
| `HEARTBEAT_HISTORY_MINUTES` | `60` | بدون تغییر IP/نام/کاربر، هر چند دقیقه یک ردیف تاریخچه ذخیره شود |
| `HEARTBEAT_RETENTION_DAYS` | `7` | مدت نگهداری تاریخچه heartbeat |

برای کاهش بار، ایجنت‌ها با ±۱۰٪ جابه‌جایی تصادفی heartbeat می‌فرستند و در حالت `--hidden` شروع اولین heartbeat تا ۳۰ ثانیه تصادفی تأخیر دارد. دیتابیس SQLite در حالت WAL با ایندکس‌های لازم کار می‌کند و تاریخچه قدیمی ساعتی یک‌بار پاک می‌شود.

### Active Directory

متغیرهای محیطی (سرور باید ویندوز باشد):

| متغیر | توضیح |
|---|---|
| `AD_ENABLED` | `true` برای فعال‌سازی |
| `AD_URLS` | مثلاً `ldap://dc1.example.local` (چند مقدار با کاما) |
| `AD_BASE_DN` | مثلاً `DC=example,DC=local` |
| `AD_PERSONNEL_ATTRIBUTE` | پیش‌فرض `employeeID` |
| `AD_AUTH_MODE` | `integrated` (پیش‌فرض) یا `credentials` |
| `AD_BIND_USER` / `AD_BIND_PASSWORD` | فقط برای حالت `credentials` |
| `AD_SYNC_INTERVAL_MINUTES` | فاصله همگام‌سازی خودکار کاربران، پیش‌فرض ۶۰ |
| `AD_SYNC_COMPUTERS` | `true` برای همگام‌سازی کامپیوترهای AD هم |

با فعال بودن `AD_ENABLED`، کاربران AD به‌صورت دوره‌ای همگام می‌شوند و هر heartbeat بر اساس username نام و شماره پرسنلی را از آن‌ها پر می‌کند. دستی هم می‌توان همگام کرد:

```
POST /api/directory   {"action":"sync-users"}
```

اگر کاربر employeeID ندارد، نام او نمایش داده می‌شود ولی شماره پرسنلی خالی می‌ماند. حساب‌های محلی (دامنه = نام کامپیوتر) با AD تطبیق داده نمی‌شوند.

## وضعیت‌ها

آستانه‌ها بر اساس فاصله heartbeat محاسبه می‌شوند (با فاصله ۶۰ ثانیه):

- آنلاین: حداکثر ۳ برابر فاصله (۱۸۰ ثانیه)
- اخیراً دیده‌شده: تا ۱۰ برابر فاصله (۶۰۰ ثانیه)
- آفلاین: بیشتر از آن

## قدم‌های بعدی

HTTPS و در صورت نیاز ایجنت سبک‌تر (Go/.NET) به‌جای Electron.
